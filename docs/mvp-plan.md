# 極限 MVP 實作與驗收計畫

## 目標與完成定義

在不做即時視訊、不建立帳號與雲端儲存的前提下，完成一個可在競賽中展示的 Streamlit 原型：使用者上傳一張網球發球獎盃姿勢側拍照，系統對可辨識的手臂顯示肩、肘、腕連線與肘關節角度，並依已確認的示範區間顯示紅色或綠色回饋。

完成不等於完成完整揮拍分析、受傷風險預測或醫療建議。任何未經教練或可信來源確認的角度數字只可作為 Demo 假設。

## 建議三階段衝刺

| 階段 | 估計時間 | 範圍 | 可交付、可驗證結果 |
|---|---:|---|---|
| 1：關鍵點與幾何 | 4 小時 | 建立最小 Streamlit 入口、讀取單張圖片、取得同側 shoulder／elbow／wrist，實作三點夾角函式。 | 對固定座標的角度函式有可重複測試；一張清晰測試照能顯示或回報缺少關鍵點。 |
| 2：視覺回饋 | 4 小時 | 疊加骨架、手臂連線與角度；用已確認的設定值決定紅／綠回饋；處理不支援檔案與偵測失敗。 | 兩張授權示例可分別走到「示範區間內」與「需調整」畫面；失敗輸入沒有偽造結果。 |
| 3：競賽證據 | 4 小時 | 錄製約兩分鐘 Demo、整理來源與限制、依主辦方實際規則準備提交材料。 | Demo 可重播；影片、README、來源／授權、隱私與競賽清單互相一致。 |

時間是規劃而非已實測工時；若 MediaPipe 與 Python 版本相容性出現問題，應先記錄並縮小範圍，而不是臨時增加視訊、雲端模型或多姿勢功能。

## 最小實作邊界

- 只接受 JPEG／PNG 的單張影像；不存檔、不串流、不連續追蹤。
- 優先由使用者選擇量測側別，或在程式可可靠判定前僅支援一側；不可猜測左右手而給出自信的評語。
- 回饋至少包含：量得的角度、使用中的示範區間、紅／綠狀態與模型無法判讀時的提示。
- 視覺疊加需讓評審看得出數學輸入：肩、肘、腕三點及兩段手臂線。
- 界面限定 Streamlit；此階段不建立 React、Next.js、原生 App、API server 或資料庫。

## 驗收清單

| 情境 | 預期結果 | 證據 |
|---|---|---|
| 已知座標的夾角函式 | 回傳與手算一致、可接受小數誤差的角度；零長向量不崩潰。 | 自動化測試或可重現的測試輸出。 |
| 可辨識的授權側拍照 | 顯示骨架／手臂線、角度及對應紅綠回饋。 | 現場操作或錄製 Demo。 |
| 看不見完整手臂、模糊或多人畫面 | 明確提示無法可靠分析；不顯示虛構角度。 | 人工測試紀錄。 |
| 不支援檔案或沒有選檔 | 不當機，提供簡短的可理解提示。 | 人工測試紀錄。 |
| 本機資料邊界 | 不在 repository、log 或雲端保存原始影像與 landmark 結果。 | 程式碼檢查與 Demo 後工作區檢查。 |
